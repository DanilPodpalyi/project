# Resume Evaluator 0.2.0

Локальный инструмент: извлекает данные из резюме, оценивает его качество,
собирает вакансии России и выдаёт рекомендации по рассмотренной выборке.
Должность и явно указанный уровень берутся из резюме. Поиск использует русские
и английские названия и морфологию; период публикаций — последние 120 дней.

Основной сценарий — **резюме → рынок → советы**. Сравнение с одной заданной
вакансией сохранено отдельной командой `compare`.

## Установка из исходного архива

Проверенная среда: Windows, Python 3.13.14, Ollama 0.35.1,
`gemma4:12b` и `bge-m3:latest`. Код требует Python 3.11 или новее;
другие версии Python и ОС не проходили полную приёмку этой поставки.

Распакуйте архив и откройте PowerShell в его корневой папке:

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m pip install --no-deps --no-build-isolation .
.\.venv\Scripts\python.exe -m resume_evaluator check
```

Активация окружения не требуется. `requirements.lock` фиксирует всё проверенное
окружение; `requirements.txt` — прямые зависимости. Модели в архив не включены.
Команда `python` должна указывать на установленный Python 3.13. Если её нет в PATH,
добавьте Python в PATH при установке или используйте полный путь к `python.exe`.
Установите и запустите Ollama, затем загрузите модели:

```powershell
ollama pull gemma4:12b
ollama pull bge-m3:latest
.\.venv\Scripts\python.exe -m resume_evaluator check --models --output-directory output/health
.\.venv\Scripts\python.exe -m resume_evaluator model-check
```

Файлы этих моделей в проверенной среде занимали около 8.7 ГБ. Это размер на диске,
а не требование к RAM/VRAM. Скорость и возможность загрузки зависят от оборудования;
контрольный запуск следует выполнить на компьютере заказчика.

## Запуск

```powershell
.\.venv\Scripts\python.exe -m resume_evaluator analyze "C:\Resumes\resume.docx" output/candidate
```

Поддерживаются TXT, DOCX, PDF с текстовым слоем и подготовленный `ResumeData` JSON.
Сканы PDF требуют предварительного OCR; встроенного OCR нет.
При отсутствии желаемой должности программа остановится с понятной ошибкой.
Неуказанный уровень не достраивается.

Результаты создаёт сама программа:

- `candidate_report.md` — компактный отчёт для кандидата;
- `candidate_report.json` — факты, рекомендации, статусы, ссылки и время этапов;
- `run.json` — идентификатор, версия программы, настройки, входные SHA-256, статус и этап;
- `.stages/` — извлечённое резюме, оценка, коллекция вакансий, профиль рынка,
  сравнение, рекомендации и техническая диагностика.

Первый запуск использует заданную папку. Следующие создают внутри неё
`run-<идентификатор>/`, сохраняя предыдущие результаты. `Ctrl+C` сохраняет статус
`interrupted`; при аварийном завершении может остаться `.run.lock`. Новая команда
создаст отдельный запуск. Автоматического продолжения прерванного этапа нет.

Дополнительные параметры:

```powershell
# Подробный Markdown; весь JSON и так содержит трассировку
.\.venv\Scripts\python.exe -m resume_evaluator analyze resume.docx output/candidate --detailed-report
# Полные вакансии из подготовленного JSON вместо HTTP-сбора
.\.venv\Scripts\python.exe -m resume_evaluator analyze resume.docx output/candidate --vacancies-json vacancies.json
# Только сбор по должности из готового резюме
.\.venv\Scripts\python.exe -m resume_evaluator collect resume.json output/collection.json --collect-only
# Старое сравнение с одной вакансией
.\.venv\Scripts\python.exe -m resume_evaluator compare resume.docx vacancy.docx output/comparison
```

Для полного списка: `python -m resume_evaluator analyze --help`.
Флаги `--resume-evaluation` и `--market-profile` подключают готовые результаты.
Оценка проверяется на совпадение имени кандидата, но одинаковое имя не доказывает
совпадение версии документа. Подключайте только артефакты нужного исходного резюме.
Российский профиль требует соответствующей коллекции с датами, страной и целью.

Если после остановки сохранились все три готовых этапа, их можно подключить явно:

```powershell
.\.venv\Scripts\python.exe -m resume_evaluator analyze output/candidate/.stages/resume.json output/retry --resume-evaluation output/candidate/.stages/resume_evaluation.json --market-profile output/candidate/.stages/market_profile.json
```

Это новый запуск по сохранённым данным. Если `market_profile.json` ещё не создан,
уберите `--market-profile`: рынок будет собран заново. Не меняйте исходный документ
между извлечением и подключением его готовой оценки.

## Настройки

```powershell
Copy-Item config.example.toml config.toml
.\.venv\Scripts\python.exe -m resume_evaluator --config config.toml analyze resume.docx output/candidate
```

Порядок: значения по умолчанию → TOML → переменные окружения. Конфигурация применяется
при старте процесса; `--config` ставится перед командой. `.env.example` служит памяткой,
автоматической загрузки `.env` нет. [Все настройки](docs/configuration.md).

По умолчанию: модель `gemma4:12b`, embeddings `bge-m3:latest`, локальный сервер
`http://127.0.0.1:11434`; 600 секунд ожидания запроса модели, бюджет запуска 3600 секунд,
HTTP 20 секунд, до 3 страниц на запрос и 80 полных карточек HH, HTTP-кеш 24 часа.
Бюджет проверяется на этапах и ограничивает ожидание запросов; он не является
принудительным завершением процесса по настенным часам.

## Доступ к вакансиям

Сборщик обращается к HH и «Работе России». Ему нужен исходящий HTTPS-доступ;
резюме в эти API не отправляется, передаётся поисковая должность. Ollama получает
текст резюме; при стандартном адресе обработка локальная. Если изменить сервер,
текст будет отправляться на указанный адрес.

```powershell
.\.venv\Scripts\python.exe -m resume_evaluator check --sources "Графический дизайнер" --output-directory output/health
$env:HH_USER_AGENT = "ResumeEvaluator/0.2.0 (your-contact@example.com)"
# Только если вы получили действующий токен приложения:
$env:HH_ACCESS_TOKEN = "<token>"
```

При проверках из среды разработчика HH возвращал HTTP 403. Токен не гарантирует
устранение запрета: заказчику требуется проверить доступ со своего компьютера
и при необходимости оформить приложение/доступ у HH. Программа сохраняет отказ
и продолжает с доступными данными. [Порядок подключения и диагностика](docs/source_access.md).

## Как понимать результат

Оценка качества резюме 0–100 относится к полноте и содержанию документа.
Модель предлагает баллы разделов, Python проверяет пределы и суммирует их.
Это не процент соответствия рынку.

Основной профиль строится по 3–6 подходящим вакансиям; смежные вакансии учитываются
отдельно. Уверенность зависит от полноты, дат, независимых работодателей и источников.
Выводы относятся к выборке, а не ко всему российскому рынку.

`evidenced` означает практическое подтверждение в задачах/опыте/результатах;
`mentioned_only` — название присутствует, но применение не показано.
Отсутствующий в тексте навык не означает, что кандидат им не владеет.
Для гибких навыков даётся краткое предложение указать их, если они соответствуют опыту.

Недостаточная выборка даёт `partial`: оценка резюме и доступные советы сохраняются,
рыночные пробелы не выдумываются. `completed` в `run.json` означает технически завершённый
запуск; смотрите также `report_status`. Код выхода: 0 — отчёт, в том числе частичный;
2 — ошибка основного CLI; 1 — провал `check`; 130 — прерывание.

## Проверки и демонстрация

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
.\.venv\Scripts\python.exe scripts/demo.py
.\.venv\Scripts\python.exe scripts/build_release.py
```

Демо не обращается к интернету и Ollama: оно использует заранее подготовленные
**вымышленные** резюме, оценку и вакансии. Оно проверяет обработку и сохранение,
но не качество текущей рыночной выборки. В `examples/resumes/` находятся предоставленные
автором вымышленные DOCX Анны Соколовой и Алексея Морозова для живых прогонов.

## Устройство и передача

```text
resume_evaluator/       активные модули, CLI, настройки и runtime
  legacy/              сравнение с одной вакансией, исторические алгоритмы
  research/            исследовательская копия
examples/resumes/      вымышленные DOCX
examples/precomputed/  воспроизводимые JSON для тестов и демо
tests/                 проверки без обязательного Ollama и сети
scripts/               демо, сборка, исследовательские инструменты
docs/                  инструкции, контракты, ограничения, приёмка
.github/workflows/     автоматическая проверка исходников
```

Старые пути модулей оставлены совместимыми. Общие модели и функции находятся в
`market_profile.py`; российский основной запуск использует builder v2.
[Архитектура и контракты](docs/architecture.md), [протокол проверки](docs/release_acceptance.md),
[готовность передачи](docs/customer_handover_readiness.md), [изменения](CHANGELOG.md).

Сборка создаёт `dist/resume-evaluator-0.2.0-source.zip`, SHA-256 архива и внутренний
манифест файлов. В архив входят код, инструкции, тесты и синтетические примеры.
Рабочие `output/`, `data/`, окружение Python, кеши, `.env`, `config.toml` и старые примеры
не поставляются. Сервер Ollama и модели устанавливаются отдельно. Условия передачи
самого исходного кода определяются соглашением с заказчиком; лицензия проекта
автоматически не назначается.
