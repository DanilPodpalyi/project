# Российский рынок по резюме

Новый сценарий берёт целевую должность и указанный seniority из `ResumeData`.
Если уровень отсутствует, он не выводится из количества лет опыта. Навыки и
опыт кандидата не передаются в построение рынка. При извлечении документов
seniority дополнительно проверяется на явное присутствие в исходном тексте.

Рынок фиксирован: Россия, последние 120 дней. Российские названия сравниваются
с помощью `pymorphy3`: падежи и числа приводятся к словарным формам, в том числе
учитываются неоднозначные разборы. Морфология влияет на ранжирование, а v2
отдельно проверяет содержание профессии и seniority.

## Запуск

Установите обновлённые `requirements.txt`. Единый кандидатский отчёт:

```powershell
python -m resume_evaluator.candidate_assessment_pipeline resume.pdf output/candidate
```

Должность отдельно вводить не требуется. Поддерживаются PDF, DOCX, TXT и
структурированный JSON. Для повторного использования оценки доступен
`--resume-evaluation`. Старый трёхаргументный интерфейс с ручной профессией
сохраняется; `--market-russia` включает в нём цель из резюме.

Только собрать данные из интернета, без рыночных LLM-вызовов:

```powershell
python -m resume_evaluator.russian_market resume.json output/russia/collection.json --collect-only
```

Для неизвестного названия должности сборщик предварительно вызывает локальную
модель для перевода названия (не более одного повтора при ошибке формата или языка).
`--no-title-translation` отключает этот
вызов: остаются исходное название, готовый словарь и успешные кешированные переводы.
Импорт `--vacancies-json` сам по себе не вызывает переводчика.

Построить `MarketProfile`:

```powershell
python -m resume_evaluator.russian_market resume.json output/russia/market_profile.json
```

## Источники

Повторное использование `--market-profile` в российском сценарии требует
соседний `*.collection.json`. Проверяются происхождение источников, страна,
должность, уровень и актуальность дат; старый иностранный профиль не будет
молча использован как российский. Дополнительные альтернативные роли в этом
сценарии также проверяются через российский сборщик.

- HH: страна `area=113`, поиск в названии, `date_from`/`date_to`, пагинация и
  загрузка полной карточки каждого объявления. Регион проверяется по дереву
  регионов России. `HH_ACCESS_TOKEN` и `HH_USER_AGENT` читаются из окружения;
  токен никогда не передаётся второму источнику.
- «Работа России»: публичный API `opendata.trudvsem.ru`, поиск по фразе,
  пагинация, поля обязанностей и требований. Период проверяется по дате
  создания; дата изменения не заменяет дату публикации. Точность даты
  отмечается как `day`.

Ошибка одного источника сохраняется и не отменяет другой. При HTTP 401/403
HH прекращает повторять поиск по остальным формулировкам. Ответы кешируются
на 24 часа. Зарубежные remote feeds в этом сценарии не подключаются.

## Импорт полных описаний

Добавьте `--vacancies-json vacancies.json` к любой из новых команд. Формат:

```json
[
  {
    "id": "unique-id",
    "name": "Аналитик информационной безопасности",
    "country_code": "RU",
    "area": {"id": "1", "name": "Москва"},
    "employer": {"id": "company-id", "name": "Работодатель"},
    "published_at": "2026-09-15T10:00:00+03:00",
    "alternate_url": "https://example.org/vacancy/unique-id",
    "description": "Полный текст обязанностей и требований...",
    "archived": false
  }
]
```

Для импорта страна должна быть явно подтверждена `country_code=RU`, а дата
содержать часовой пояс. Поискового snippet недостаточно. Короткий текст
(меньше 200 знаков или 20 слов) считается `sparse` и не идёт в нормализацию.
Порог является проверкой достаточности текста, а не доказательством наличия
всех требований. Дату примера нужно заменить актуальной при использовании.

## Результаты и полнота

`market_profile.collection.json` содержит оригинальные описания, очищенные
полные тексты, ссылки, работодателей, регионы, даты, сигналы морфологии,
статусы полноты, ошибки HTTP и причины исключения. Счётчики показывают исходные
ответы и количество пригодных уникальных описаний по источникам.
Одинаковая карточка на разных площадках не повышает частоту требований.
Копии сохраняются в `duplicate_copies` с оригинальным описанием, а причины
удаления — в диагностике. Разные объявления одного работодателя сохраняются;
независимость работодателей учитывается отдельно.

Кэш извлечения требований учитывает цель, полное описание и название вакансии.
Одинаковый текст при разных названиях и уровнях обрабатывается отдельно.
Версия ключа обновлена: записи старого кэша, не учитывавшие название, повторно
не используются. Счётчик дублей также сохраняет повторы между запросами,
которые были удалены ещё до загрузки полной карточки.

Поиск по умолчанию использует русское и английское названия одной должности.
Для известных профессий используются готовые эквиваленты:
`Graphic Designer` / «Графический дизайнер», а также `Machine Learning Engineer`,
`ML Engineer`, «Инженер машинного обучения», «Инженер по машинному обучению»
и `ML-инженер`. Они добавляются в запросы и учитываются при морфологическом
сопоставлении названий, включая склонения. Для остальных должностей локальная
Gemma возвращает два варианта по JSON-схеме. Ей передаётся только название,
без текста резюме, навыков, опыта и контактов. Проверяется сохранение исходного
названия, языка, уровня и технических обозначений; сомнительный перевод отклоняется.
Успешный перевод кешируется по названию, модели и версии переводчика.

Максимум — шесть запросов; исходный вариант и оба языка идут перед леммами.
Указанный уровень сохраняется отдельным запросом, по возможности на обоих языках.
Дополнительные специализации в названии не удаляются; составная узкая цель
переводится целиком и не расширяется до общей профессии.
Data Scientist, Data Engineer и DevOps не считаются эквивалентами ML-инженера.
Машинный перевод повышает приоритет объявления, но не становится доказанным alias:
соответствие профессии и уровню проверяется по содержанию вакансии. Если переводчик
недоступен или не уверен в эквивалентности, поиск продолжается по исходному названию;
причина сохраняется в `diagnostics.search_titles` соседнего `*.collection.json`.

Сбор не отбрасывает текст после первых 2500 символов. Новый normalizer отправляет
каждое полное описание отдельно, сохраняет собственный кеш и диагностирует
ошибки извлечения. Тексты больше 24000 символов явно исключаются с причиной
`full_text_exceeds_model_budget`, без скрытого обрезания.

Сбор ограничен тремя страницами на запрос. Для HH загружается до 80 отдельных
карточек; downstream получает до 80 описаний и проверяет релевантность порциями
по 20. После ошибок извлечения и несовместимого seniority происходит добор из
резерва. Основной профиль использует 3–6 прямых вакансий; до шести смежных
сохраняются отдельно как `adjacent_context`. Достижение поискового лимита видно
в диагностике. Результат описывает доступную выборку, а не весь рынок России.

Общий кандидатский отчёт показывает страну, период, число полных описаний и
ссылку на артефакт сбора. Смежные вакансии и их требования показаны отдельным
блоком возможного развития, с собственными частотами и ссылками. Они не
повышают основные требования и не становятся пробелами кандидата.

Синонимы требований объединяются внутри каждой выборки. Например, «анализ
логов», «анализ журналов» и `log analysis` дают одну компетенцию. Все формы и
их источники сохраняются; частота считается один раз на вакансию. Подробности
и ограничения описаны в [MarketProfileBuilder v2](market_profile_v2.md).

Уверенность учитывает независимых работодателей, прямые совпадения, полноту,
свежесть публикаций и площадки. Значение `low` сохраняется до рекомендаций.
Совет содержит шаги, ожидаемый результат, частоту требования, примеры вакансий
и подтверждения из резюме. Если подтверждение не найдено, предлагается сначала
уточнить реальный опыт, а затем при необходимости рассмотреть обучение.

Старые исследовательские копии и сравнение с одной
вакансией продолжают использовать свои прежние интерфейсы.

Официальные описания API: [HH](https://api.hh.ru/openapi/redoc),
[«Работа России»](https://trudvsem.ru/opendata/api).
